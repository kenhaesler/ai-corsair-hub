Function evidence = REA `decompile`/`trace`/`xrefs` with the evidence_ids cited below (first 20 hex chars shown). Addresses are image VAs (base 0x180000000). ## 1. Summary
- **Device source of truth is a layered module graph, not one enumerator.** `HidEnumerator` (raw HID via SetupAPI/hid.dll + window-message hotplug) → `UsbDeviceListing` (VID/PID "DeviceUsbId" list, settle timer) → `DeviceListing` (aggregator + filter, prefers LLAccess/USB over WMI) ; `WmiDeviceListing` is a *fallback/extra* source for CLink + DRAM only; `LegacyEnumerator` is the pre-Bragi channel enumerator and does no Win32 enumeration itself (no SetupAPI/CM imports).
- **Enumeration API = SetupAPI by interface GUID**: `SetupDiGetClassDevsW(guid, NULL, NULL, 0x12 = DIGCF_PRESENT|DIGCF_DEVICEINTERFACE)` → `SetupDiEnumDeviceInfo` → `SetupDiGetDeviceInstanceIdW` → `CM_Locate_DevNodeW` → `CM_Get_Parent` → `CM_Get_Device_IDW` (parent ID) → `SetupDiGetDeviceRegistryPropertyW` (DEVICEDESC/FRIENDLYNAME(0xC)/HARDWAREID(1)/ENUMERATOR_NAME(0x16)). hidapi-style `HidD_*` is used only after open.
- **Hotplug = hidden window + `RegisterDeviceNotificationW(DBT_DEVTYP_DEVICEINTERFACE)` per interface GUID, plus per-handle `DBT_DEVTYP_HANDLE` registrations** on opened devices (QUERYREMOVE closes the handle immediately; REMOVECOMPLETE drops the instance). Arrival is *queued* and handled by a separate worker thread, which first waits for `CMP_WaitNoPendingInstallEvents(1000)` (PnP driver-install quiescence) – that is the real debounce.
- **Candidate filter**: instance parsed from path with regex `\w+#vid_\w+&pid_\w+[\w#&]+`; accepted only if enumerator name ∈ {usb, hid, hdaudio, pci}; VID/PID parsed from hardware-ID (`vid_`/`ven_`, `pid_`/`dev_`); then a filter list of `{usb-vid, usb-pid}` maps (pushed down from DeviceListing/service `setUsbDevicesFilter`) is applied. VID/PID lists are *data-driven* (device definitions in CueSettings), not hard-coded in these DLLs. BLE (`Bluetooth Low Energy` enumerator) is explicitly rejected in UsbDeviceListing.
- **Composite grouping** is by the **parent device instance ID** (`CM_Get_Parent`) stored per interface instance; USB listing keys by `DeviceUsbId{vid,pid}` and keeps a list of instances per key.
- **Identity per instance**: `DeviceInstance{path, transport, instanceId, parentId}` + VID/PID (u16 at +0xA8/+0xAA) + description/friendly flag. Serial string is read lazily from the open handle (`HidD_GetSerialNumberString`, async). No container ID, no location info found.
- **`CorsairDeviceListerService`** is a Windows service ("Corsair iCUE service for device detection") hosting DeviceDetector + HidEnumerator + DeviceLister, exposing them over Qt RemoteObjects (`DeviceListerServiceIpc`, address key `CorsairDevListerServiceAddress`) with a private-namespace shared-memory block for address hand-off; it auto-exits on inactivity. iCUE sets the VID/PID filter via `setUsbDevicesFilter`.
- Not found / unknown: settle-timer interval, exact interface GUID list registered, HID usage-page filtering (caps are stored, consumer not located), OS-level handling of device-open sharing flags.

- WndProc `FUN_180019a60` (ev_c207dbf492c92ac3a4df337b6bd2e01f575ee8a5): `WM_DEVICECHANGE (0x219)`:
  - `0x8000 DBT_DEVICEARRIVAL` & `dbch_devicetype==5` → under CRITICAL_SECTION calls `FUN_180016ba0` (ev_0038f9e0e710831e) which just **appends `{GUID, path}` to a pending vector** (stride 0x30) → `SetEvent(pending)`. Log text `"DD: DBT_DEVICEARRIVAL"`.

### F4 Candidate filtering (observed + inference)
1. Path regex `\w+#vid_\w+&pid_\w+[\w#&]+` (`FUN_180012e00`, ev_18e3fa91884abf32, string 0x180028798) – normalises/validates `hid#vid_1b1c&pid_0c3f&mi_00#…` style paths. (Role inferred from name.)
2. Enumerator name must be `usb|hid|hdaudio|pci` (`FUN_180017560`); `hdaudio` and `pci` use `ven_/dev_` instead of vid/pid (so iCUE also tracks audio endpoints and PCI devices such as GPUs/RAM controllers).
3. VID and PID must both be non-zero (`FUN_180004f50`).
4. Filter list `Add filter:` (`FUN_180009050`, ev_42707c59c69a261a) / `filter out insertion:` (`FUN_18000a610`, ev_3b943609d0a61aef) – `HidEnumerator` keeps a vector of filter objects; an insertion matched by any filter's virtual `+0x30` predicate is *not* processed. DeviceListing builds the filter content from maps with keys **`usb-vid`**, **`usb-pid`** (`FUN_180004980`, ev_1f2a9055076056fac; invalid ones logged `"Skipping invalid filter IDs:"`), messages `"Applying USB devices filter..."`, `"USB devices filter's applied."`. The VID/PID *lists* therefore come from device definitions (CueSettings `DeviceUsbId`) – no static list in these binaries.
5. `CM_Get_DevNode_Status` problem/status mask rejection at open time (F3).
6. HID attributes/caps are read after open (`FUN_18001ff50` → `HidD_GetAttributes`, returns ProductID, `FUN_18001fdc0` → `HidP_GetCaps` stored as 0x40-byte blob at +0xD0) – usage page/usage/report sizes are available to processors, but **I did not find a usage-page filter in the enumerator itself** (unknown whether processors filter on it).
7. Interface number (`MI_xx`): no literal `mi_` token string was found in HidEnumerator; selection of the data interface appears to happen in the per-device-family HID processors (outside scope), not in enumeration.

### F5 Grouping / processors (observed + inference)
- `HidProcessorsManager` (RTTI strings, `FUN_18000ebd0` ev_3f42021fad26f6f6): processors register with a `HidPriority` and a list of `(HidDeviceDescriptor, DeviceInstance)` pairs; log strings `"Add … with … priority"`, `"already has exclusive mode. Ignore it for"`, `"used with lower priority"`, `"Invoke replug for"`, `"returns invalid HidInsertRespond for"`, `onDeviceOpenFailed`, `processDeviceReady`, `processDeviceRemove`, `releaseDevice` ("released for all processors. Close device"). Model: one open handle per interface shared among multiple interested processors (reference-counted "released for all processors"); exclusive-mode owner wins; a lower-priority processor can be told to "replug" when the owner releases.
- `HidDeviceManager` runs `OpenHid{%1,%2ms}` / `CloseHid{%1}` tasks on a dedicated worker thread with a priority task queue (`FUN_180006180`, ev_83f2ad2ab69d9e3d "Start worker thread", `_Cnd_wait`) – HID open/close is serialised off the notification threads.
- Composite grouping: each instance stores `parentId` (`CM_Get_Parent` of the interface devnode = the composite USB device) – `DeviceInstance` ToString `FUN_180012b90` (ev_d1c81ad10f6596f6) prints `DeviceInstance{path: …; transport: …; instanceId: …; parentId: …}`. Interfaces of one physical device share the same parentId (inference; the grouping consumer was not traced). UsbDeviceListing additionally buckets by `DeviceUsbId(vid,pid)` and compares instance sets.

### F6 Stored identity (observed)
Per instance: device interface **path**, **transport** (= SPDRP_ENUMERATOR_NAME: usb/hid/hdaudio/pci/…), **instanceId**, **parentId**, VID, PID, description + flag (friendly vs. device-desc). Serial / manufacturer / product are *not* stored at enumeration; they are fetched on demand from the open handle (`WindowsHidDevice::serialNumber/productName/manufacturerName/usbString` lambdas, `HidD_GetSerialNumberString`, `HidD_GetIndexedString`). Strings contain no `ContainerId`, `LocationInfo` or `BusReportedDeviceDesc` → not used. Legacy module has `DeviceSerialNumberFormat` and `RequiresExtendedPidDetection` settings (strings) – serial formatting is per device definition.

### F7 CorsairDeviceListerService (observed strings, inference on mechanism)
- Purpose string: `"Corsair iCUE service for device detection"`; installable service (`CreateServiceW/DeleteService/ChangeServiceConfig2W`, CLI verbs Install/Uninstall/Start/Stop/Pause/Resume).
- Requires modules `DeviceLister` and `HidEnumerator` (`"Missing required system DeviceLister"/"…HidEnumerator"`); runs `DeviceDetector{%1}` (modes via `cue::dev::DeviceDetector::Mode`), `"Start device detection"`.
- IPC: Qt RemoteObjects source `DeviceListerServiceIpcSource/SimpleSource` (`cue::dev::lister_svc::IpcServer`), registry key `CorsairDevListerServiceAddress`; signals `devicesChanged`, `devicesReady`, `enumerationCompleted`; slot `setUsbDevicesFilter(QList<DeviceIds>)` (`"Setting USB devices filter..."`); log `"Lister state changed:"`, `"Devices ready:"`. Address hand-off through named file mapping in a **private namespace** (`CreateBoundaryDescriptorW`, `AddSIDToBoundaryDescriptor`, `SeCreateGlobalPrivilege`, `"Failed to create shared memory …"`, `"Failed to open named mutex"`, `boundary_…`); the WmiDeviceListing module also carries the same ACL/mapping code plus `tcp://127.0.0.1:0`, i.e. a loopback TCP listener whose port is published via that shared memory (inference).
- `"Requesting service shutdown due to inactivity"` – idle self-stop (`Sleep` polling); `"Error during service startup sequence. Manual restart may be required"`.
- Rationale (inference): run enumeration as a service so detection works before login / without elevation and so multiple iCUE clients share one hotplug listener.

## 3. Comparison vs ai-corsair-hub
Repo: `crates/hid/src/discovery.rs` (`DeviceScanner`: `HidApi::new`, `refresh_devices`, `device_list` filtered by `VID==0x1B1C`, key `pid:serial`, `open_device(pid, serial, interface)`). Callers: `apps/service/src/main.rs:48`, `crates/fancontrol/src/control_loop.rs:186,231-285` (re-scan on error), `apps/scanner`, `apps/rgb-test`.

Gaps:
1. **No hotplug**: enumeration is poll/refresh-on-error only; no arrival/removal events, no `DBT_DEVTYP_HANDLE` removal handling, so a USB re-enumeration (sleep/resume, hub reset) is noticed only when a read/write fails. iCUE closes handles on QUERYREMOVE and reopens on QUERYREMOVEFAILED.
2. **No PnP-settle debounce**: right after arrival, driver install may be incomplete; iCUE waits `CMP_WaitNoPendingInstallEvents` and checks `CM_Get_DevNode_Status` problem bits before `CreateFile`.
3. **Identity = (pid, serial)**: breaks if serial missing/duplicated (two identical hubs without serials, `"unknown"` fallback) and loses relation to the PnP tree; iCUE keeps path + instanceId + parentId (composite parent) and VID/PID. Grouping by serial is okay for the two hubs (distinct serials) but not robust.
4. **Filter is VID-only + PID→enum**: no enumerator-name/transport filter (BLE/Bluetooth HID vs USB), no problem-status check, no data-driven VID/PID allow-list.
5. **hidapi `refresh_devices` re-enumerates everything** on each call (heavy; and it re-opens SetupAPI handles each time); iCUE enumerates once and then updates incrementally from notifications.
6. **No single-owner/handle-sharing manager**: multiple components (`control_loop`, rgb, scanner) may race opening the same interface; iCUE serialises open/close on one worker with priority/exclusive semantics.
7. No separate low-privilege/system-level detection service; `apps/service` is a stub.

## 4. Recommendations (prioritised, Rust-implementable)
1. **Add a hotplug listener in `crates/hid`** (new module `hotplug.rs`), using `windows`/`windows-sys` crate: hidden window thread (`RegisterClassW`, `CreateWindowExW`, `GetMessageW` loop) + `RegisterDeviceNotificationW(DBT_DEVTYP_DEVICEINTERFACE, GUID_DEVINTERFACE_HID)`; or simpler/more robust `CM_Register_Notification` (`CM_NOTIFY_FILTER_TYPE_DEVICEINTERFACE`, callback → `std::sync::mpsc`/tokio channel; no window needed). Emit `Arrived{path}`/`Removed{path}` events into the existing control loop. This replaces ad-hoc "rescan on error".
2. **Debounce**: on arrival, coalesce for ≥ settle window (suggest 500 ms–1 s, reset on each event) and, before opening, `CMP_WaitNoPendingInstallEvents` is undocumented (setupapi.dll export) – instead poll `CM_Get_DevNode_Status` until no `DN_HAS_PROBLEM`/`DN_STARTED` is set, with timeout 5 s. Keep priority: iCUE’s ordering is event → wait PnP idle → open.
3. **Per-handle removal notifications**: after `CreateFileW` register `DBT_DEVTYP_HANDLE` (or `CM_Register_Notification` with `CM_NOTIFY_FILTER_TYPE_DEVICEHANDLE`); on QUERYREMOVE drop the handle immediately (stops Windows from stalling uninstall/sleep), on QUERYREMOVEFAILED reopen.
4. **Richer identity struct** replacing `(pid, serial)`: `DeviceIdentity { vid, pid, interface_path, instance_id, parent_instance_id, enumerator, serial: Option<String> }`; fetch `instance_id` via `SetupDiGetDeviceInterfaceDetail` + `SetupDiGetDeviceInstanceId` (or `CM_Get_Device_Interface_PropertyW(DEVPKEY_Device_InstanceId)`), parent via `CM_Get_Parent`/`CM_Get_Device_IDW`; group interfaces by `parent_instance_id` (composite), keep serial only as a display/match hint. Persist config bindings by `(vid,pid,serial)` but fall back to parent instance path when serial absent.
5. **Filtering**: restrict to `enumerator ∈ {USB}` (reject `BTHLE*`), require non-zero VID/PID, keep an explicit allow-list `[(0x1B1C, 0x0C3F), (0x1B1C, 0x1C1F)]` in `crates/common`, and select the data interface by `interface_number`/usage page after enumeration (hidapi already exposes both).
6. **Open serialisation**: one `HidManager` thread/actor owning handles (open, close, release-on-QUERYREMOVE) with an mpsc command queue; other tasks request a lease. Mirrors `HidDeviceManager`'s worker queue.
7. **Optional later**: move detection into `apps/service` and publish state via local IPC (named pipe) – only worth it with Phase 6 service work.
